# 第四部分：游戏核心设计

## 4.1 游戏背景

游戏画面包含：

- 上方彩色沙块传送带
- 中间游戏操作区域
- 下方颜色收集桶
- 顶部关卡和分数
- 底部游戏控制按钮

玩家需要通过选择收集桶，将传送带上的彩色沙块进行分类收集。

当桶内收集到规定数量的同色沙块时，自动触发清空和奖励。

完成关卡目标即可通关。

## 4.2 颜色配置

第一版使用四种颜色：

红色：#FF5B5B

黄色：#FFC857

蓝色：#4D9DE0

绿色：#59C98A

颜色必须具有良好的区分度。

不要使用视觉上过于接近的颜色。

## 4.3 初始游戏参数

- 颜色数量：4 种
- 收集桶数量：4 个
- 每个桶容量：5
- 每个桶只接收对应颜色
- 传送带显示当前沙块和后续沙块
- 每个关卡有明确目标
- 玩家通过点击桶进行收集

以上数值应当可通过配置文件修改。

## 4.4 核心操作流程

1. 传送带显示当前沙块序列。
2. 玩家观察即将到来的颜色。
3. 玩家点击一个收集桶。
4. 系统检查当前可收集沙块。
5. 如果颜色匹配且桶有空间，执行收集。
6. 沙块飞入对应桶。
7. 桶内数量增加。
8. 达到容量后触发消除。
9. 播放消除动画和音效。
10. 桶清空并获得分数。
11. 继续下一次操作。
12. 完成关卡目标后进入胜利界面。

## 4.5 必须明确的游戏规则

- 颜色匹配：允许收集。
- 颜色不匹配：禁止收集，提供错误反馈。
- 桶没有空间：禁止收集。
- 桶满且完成目标：自动清空。
- 所有桶都无法接收当前沙块：进入失败状态。
- 所有目标完成：进入胜利状态。
- 暂停状态下不能继续收集。
- 游戏结束后不能重复计算分数。

## 4.6 增加策略性

游戏不能只是无脑点击。

必须加入：

- 传送带颜色顺序。
- 后续颜色预览。
- 独立桶容量。
- 颜色连续组合。
- 颜色交错排列。
- 收集顺序规划。
- 有限的操作空间。

玩家需要思考先收集哪一种颜色。

重要：

如果只有固定颜色桶、每个颜色只有一个对应桶，玩家可能缺少选择空间。

请评估是否需要引入有限容量、队列阻挡、预览信息等机制，增加策略性。

不要为了增加策略而破坏规则的直观性。

请在开发报告中解释最终采用的规则。

# 第六部分：动画与反馈

这是游戏品质的核心。

## 6.1 沙块动画

必须实现：

- 沙块沿传送带移动
- 沙块位置平滑变化
- 点击后飞入对应桶
- 收集时缩放
- 收集后消失

## 6.2 桶动画

必须实现：

- 桶被填充时轻微弹跳
- 数量增加时进度变化
- 桶满时放大反馈
- 桶清空时粒子动画
- 消除后恢复初始状态

## 6.3 操作反馈

- 正确操作有积极反馈
- 错误操作有轻微抖动
- 连续消除显示 COMBO
- 通关时有庆祝动画
- 点击按钮有按压效果

## 6.4 动画技术

使用 requestAnimationFrame。

要求：

- 动画不能阻塞游戏逻辑
- 不能重复创建动画循环
- 暂停后停止更新
- 恢复后正确继续
- 不出现动画重复触发
- 不出现物体位置跳动
- 使用合理的缓动函数

# 第七部分：关卡系统

第一版必须实现至少 30 个关卡。

## 7.1 难度划分

第 1～5 关：

- 2～3 种颜色
- 简单颜色排列
- 让玩家理解操作

第 6～10 关：

- 3 种颜色
- 增加连续颜色组合
- 适当增加收集数量

第 11～20 关：

- 4 种颜色
- 增加交错排列
- 提高规划难度

第 21～30 关：

- 4 种颜色
- 更复杂的颜色序列
- 更高的策略要求

## 7.2 关卡数据

关卡数据必须独立于游戏逻辑。

建议使用 JSON 或 JavaScript 配置。

每个关卡包含：

- levelId
- colors
- conveyorSequence
- bucketCapacity
- targetCount
- difficulty
- scoreThresholds

## 7.3 关卡质量

必须保证：

1. 所有关卡可以通关。
2. 不存在初始无解关卡。
3. 不存在错误目标数量。
4. 不存在无法触发的胜利条件。
5. 难度逐步递增。
6. 不要简单重复随机排列。
7. 每关具有一定变化。

编写关卡验证程序。

如果关卡使用随机生成，必须提供确定性种子和可复现的测试方式。

使用自动模拟验证关卡是否可解。

# 第八部分：分数和奖励

基础得分：

- 每收集一个沙块：+10
- 完成一个桶：额外 +50
- 连续完成桶：触发 Combo
- 完成关卡：额外奖励

星级：

- 1 星：完成关卡
- 2 星：达到指定分数
- 3 星：达到更高分数

每关的星级门槛根据难度合理设置。

分数不能重复计算。

失败后是否保留分数，规则必须统一。
